`tests/ruleset-freeze.test.mjs` hashes the **sources** of the rule files, so
adding code to `regime-filters.ts` / `run.ts` changes their hashes even when the
shipped behaviour does not. Per that test's own re-freeze policy the hashes are
re-recorded here, in the same change, with the evidence that the shipped rule set

The freeze's second test — the shipped configuration, the filter defaults
(`enableFilterC ?? true`, `enableFilterF ?? true`), and the golden lock — passes
unchanged, and `tests/research-filters.test.mjs` pins dormancy directly: with the

flags are absent from both shipped configurations
(`ANALYZER_LIVE_OPTIONS` / `ANALYZER_CERTIFIED_OPTIONS`), which a test also pins.

This is therefore **not** a new forward-validation window for the shipped rules:
their evaluation window is untouched, and the candidates have no window yet —

"Removed" counts trades the C+F book takes that the candidate rejects; "own R" is

number can ever promote a candidate.

## 5. Design rules honoured (from the freeze document)

1. **Entry-time only** — every predicate reads the signal bar and strictly prior
   history; pinned by a truncation test per candidate (the decision is identical
   when the series is cut at the signal bar).
2. **Fail-open** — missing inputs never reject; pinned per predicate (undefined
   entry, missing prior day, zero-width prior range, incomplete EMA stack,
   insufficient ATR window, non-finite ATR, missing OHLC, unparseable datetime).
3. **No slot consumption on reject** — pinned behaviourally: the locked baseline
   contains 48 / 84 / 16 / 37 trades (D / H1214 / Doji+highVol /
   doji+compressed) that can only exist because a candidate rejection left the
   de-dupe slot free.
4. **Applied after C and F** — pinned by an ordering test: no `FILTER_X` row
   would also have been rejected by Filter C or Filter F.
5. **Defaults OFF** — `enableFilterX ?? false`; pinned by the dormancy test.
6. **No threshold tuning** — the constants above are the discovery vocabulary,
   frozen; the tests pin the discovery fingerprints so a silent edit fails.

## 6. What is deliberately NOT here

- No production default changed, and no call site sets a candidate flag.
- No stacking: the candidates are evaluated one at a time, and the harness runs
  each against its own baseline.
- No batch-only `htfConflict` — it stays unimplemented until an engine-exact
  definition is written and frozen separately.
- No use of `similar_swing_*` / `swing_invalidated` (lookahead columns).
