Date: 2026-09-30

## 1. The backtest refused to run — warm-up could not clear the bar floor

**This is the "it won't even run a backtest" bug.**

The analyzer refuses any series below `MIN_PRODUCTION_BARS` (1,000 bars):
under that depth the warm-up is not saturated and the newest bar's decisions
differ from a full-history run (`src/lib/analyzer/series-contract.ts`). The
backtest fetched `range − 30 calendar days` of warm-up before the first
analysed day (`STANDARD_LOOKBACK_CALENDAR_DAYS = 30`).

A 30-minute session day is 48 bars, so 1,000 bars needs ~21 trading days —
i.e. **29–31 calendar days with zero closures**. Any holiday in the window
pushes the series under the floor, and the run aborts with
`Series rejected: history depth N bar(s) is below the production floor of 1000`
before a single trade is priced.

Measured over the locked baseline (2025-11-01 → 2026-08-20, 9,738 rows):

| Warm-up | Worst window in the baseline | Windows under the floor |
| ------- | ---------------------------- | ----------------------- |
| 30 d    | 714 bars (−29%)              | 24 / 140 (17%)          |
| 38 d    | 1,002 bars (+0.2%)           | 0                       |
| 46 d    | 1,242 bars (+24%)            | 0                       |

End-to-end through the real generator+analyzer (single-day backtests sampled
across the baseline): **30 d rejected 2 of 24 runs; 46 d rejected 0 of 22**,
worst series 1,416 bars (42% headroom).

**Fix.** `src/lib/pipeline/policy.ts` now *derives* the warm-up from the floor
it has to satisfy, so the two can never drift apart again:

```
STANDARD_LOOKBACK_CALENDAR_DAYS =
  ceil(MIN_PRODUCTION_BARS / BARS_PER_SESSION_DAY  ×  7/5  ×  1.55)  = 46
```

`1.55` is a closure margin for exchange holidays and the export's trimming of
the weekly closure (the 7/5 already covers weekends).

**The generator had the same bug, worse.** Its default OHLC range was
`today → today`: ~48 bars, which the analysis page rejects **every single
time**. The default is now the floor-clearing window, and the page warns in
place when a manually chosen range is too short.

## 2. The OHLC export was quadratic — the biggest remaining cost of a long run

`enrichOhlcRows` (`src/lib/ohlc-generator.ts`) computes the swing columns the
analyzer's whole trend layer reads. Three of its scans grew with the square of
the series length. Measured with a mocked provider feeding date-shifted copies
of the baseline:

| Series          | Before  | After  |
| --------------- | ------- | ------ |
| 9,738 candles   | 846 ms  | 577 ms |
| 19,476 candles  | 2,050 ms | 917 ms |
| 38,952 candles  | 6,738 ms | 1,866 ms |

Per-doubling ratio: 2.4× then 3.3× (quadratic) → **1.6× then 2.0× (linear)**.

1. **"Nearest prior opposite swing"** — `[...rows.slice(0, i)].reverse().find(...)`
   copied and reversed the entire prefix once per swing. It is exactly "the last
   swing of the other type seen so far", so it is now two running indices.
2. **`swingInvalidated`** — `rows.slice(i + 1).some(...)` copied the whole
   suffix once per swing. The question is a suffix extreme, so it is answered by
   one precomputed suffix max/min of `close`.
3. **Similar-swing candidates** — `rows.filter(...)` over the *full* row table
   once per swing, plus a second array for the session split, then a sort of
   the entire candidate list before taking five. Now one pass over the prior
   swings (only swings can ever be candidates) with a bounded top-five
   insertion using the identical comparator.

`tests/enrich-equivalence.test.mjs` re-implements all three scans verbatim and
compares the values they are allowed to affect (`swingRange`,
`swingInvalidated`, `similarSwingRefs`, `similarSwingRetracePct`,
`similarSwingContinuedPct`) on the locked baseline and on synthetic series
including plateaus, monotone runs and short prefixes. It also pins that a swing
never references itself.

## 3. Smaller fixes

- **The UI could not paint during a run.** The engine pass is synchronous and
  holds the main thread for seconds; nothing repainted until it returned, so
  the progress bar, the current-day readout and Stop all appeared frozen. The
  page now yields to the event loop before the pass (the v1.10 day-loop yield
  every 64 days is kept, and now shares one helper).
- **A failed data pull reported the wrong reason.** `buildOhlcCsv` signals
  failure only by returning `null` (its real reason — provider error, export
  validation, empty window — goes through `log`), so the backtest toasted a
  generic "no usable OHLC data for continuous window". The generator's failure
  lines are now captured and surfaced.
- **A shallow series now says what would fix it**, instead of only naming the
  gate (the provider row cap drops the oldest rows first — split the range).
- **`parseCsv`**: the per-row splitter built every field one character at a
  time. Unquoted records (the common case) now take a slice-based path, and
  `num()` avoids its sanitising regex for plain numerals. 204 ms → 156 ms on
  the baseline.
- **Duplicate date arithmetic removed**: `backtest/engine.ts#addUtcDays` now
  delegates to a new `analyzer/time.ts#addCalendarDays` instead of re-deriving
  UTC day arithmetic.

## 5. Known, deliberate, and left alone

- **Report size still grows with days².** Every day file reprints the
  cumulative per-strategy table and the "SKIPPED DAYS SO FAR" list by design
  (≈3.8 MB for the 293-day baseline). That is report content, not analysis;
  cutting it changes what a day file contains. A multi-year single run will
  produce a very large ZIP.
- **The engine pass is still synchronous.** Now linear, but a multi-year range
  still blocks for seconds. Making it non-blocking needs a Web Worker.
- **The fetch path is provider-bound**: one sequential request per 90-day
  chunk, with 60 s cooldowns on a rate-limited key.
- **`ohlc-generator.ts` is not in the ruleset freeze**, although it produces
  `similar_swing_refs` → `candle.trend` → Filter C/F. Adding it is a product
  decision (it needs a re-baseline), so it is flagged here rather than done.
- PR #15 (v1.10) was open and unmerged; its work is included here.
