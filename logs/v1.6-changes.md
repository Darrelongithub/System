# v1.6 — Engineering Audit & Hardening Pass

Date: 2026-09-08
Scope: full-repository engineering audit (reconnaissance → prioritized findings → hardening → verification).

---

## 1. Project summary

"System" (ForexLens) is a TanStack Start (React 19 + TanStack Router 1.x + Vite 8 / Nitro) SPA that ingests OHLC CSV / Twelve Data candle data and runs a **deterministic, source-matched technical-analysis engine** over it. The analyzer (`src/lib/analyzer/**`) is the core value: CSV parsing → validation → market-structure/indicator computation → a registry of trading strategies (9 "locked" production strategies + 7 context/diagnostic tools + 2 legacy research strategies) → spread/RR math → forward-looking TP/SL resolution. A backtest/journalling layer (`src/lib/backtest/**`, `src/lib/pipeline/**`, `src/lib/journal/**`) produces per-day reports and rolling stats. The UI (`src/pages/*`) drives generation of TradingView-style chart PNGs, OHLC CSV export, live analysis, and a backtest console.

Key architectural facts that shaped the audit:

- **Correctness is golden-locked.** A `tests/` harness pins exact trade counts and aggregate R (`2323 trades / R 523.6813503963194`). Strategy definitions are frozen; comments repeatedly warn that "fixing" things like SMA-vs-EMA signal lines or Ichimoku displacement would silently invalidate locked backtests.
- **Secrets are server-side only.** Twelve Data keys live in `process.env`, loaded by `src/lib/server-env.ts` (edge-safe, dynamic `node:*` imports), and the client only ever talks to `POST /api/market-data`, which proxies to Twelve Data and rotates keys.
- **Security baseline is solid.** CSRF middleware is explicitly re-enabled in `src/start.ts` (serverFn-scoped); SSR errors are wrapped by `src/server.ts` + `src/lib/error-capture.ts`; the error page is static HTML with no reflected user data.
- **No `dangerouslySetInnerHTML` with user data.** The only use is `src/components/ui/chart.tsx`, which interpolates a static theme/CSS table (standard shadcn pattern) — not user input.

## 2. Biggest weaknesses (honest assessment)

1. **An unbounded retry loop could hang the UI** (`src/pages/DataGenerator.tsx` — `fetchCandleData`). A persistent Twelve Data rate limit retried forever (`while (true)` + 60s sleeps), leaving `isGenerating` stuck `true` with no Stop button. The OHLC path already bounded this; the chart path did not. **This was the highest-value fix.**
2. **Pervasive `any` typing and hand-rolled string logic** in the data pipeline (`src/lib/ohlc-generator.ts` ~1277 lines, `src/pages/DataGenerator.tsx`). Correct today, but fragile: implicit-`any` arrays, `parseFloat` on API fields with no NaN guard at the boundary, and `any`-typed `candleData` flow from API → SVG → ZIP.
3. **Outcome classification via string-matching on `statusNote`** in two helpers (`src/lib/pipeline/continuous.ts#outcomeOf`, `src/lib/analyzer/run.ts#resolvedWinRate`). It mostly short-circuits on the structured `row.outcome`, but the fallback is brittle ("TP hit"/"SL hit"/"Turtle exit"/"stop hit" substring checks).
4. **Pre-existing lint debt.** `eslint .` reports ~63 errors repo-wide (prettier formatting drift + `@typescript-eslint/no-explicit-any`), and `noUnusedLocals/noUnusedParameters` are disabled in `tsconfig.json`, which is why several dead imports accumulated unnoticed. Fixing all of it would be a large, risky, preference-driven rewrite — deliberately deferred (see §7).
5. **No request cancellation.** In-flight generation fetches can't be aborted (no AbortController wired through `requestMarketData` → the route → Twelve Data). Mitigated but not solved by the bounded retry.

## 4. What changed (hardening applied)

All edits are small, deliberate, and behavior-preserving except where a bug was clear (H1, M1).

1. **H1 — bounded rate-limit retry** in `src/pages/DataGenerator.tsx` `fetchCandleData`. Replaced `while (true)` with a loop capped at `MAX_RATE_LIMIT_RETRIES` (imported from `ohlc-generator.ts`), aborting with a clear log line after the retries are exhausted. Non-rate-limit failures still return `[]` immediately, so normal error handling is unchanged.
2. **M1 — inverted date-range guard** in `handleGenerate`. Rejects `endDate < startDate` with a toast before any work begins.
3. **L1 — `unescape()` → `TextEncoder`** base64 conversion in `svgToPng` (removes a deprecated API and its lone-surrogate edge case).
4. **L1/L2 — dead imports removed**: `Settings`, `Play`, `Calendar`, `Key`, `AlertCircle` (DataGenerator); `Bot` (AnalysisV2).
5. **L3 — dead data/comment cleanup** in `src/lib/backtest/engine.ts`: removed the orphaned `fvg_fill` `REQUIREMENTS` entry and the stale `fvg-fill.ts` reference.

## 6. Remaining risks & tech debt

- **Lint debt** (`no-explicit-any`, prettier drift) across `src/pages/DataGenerator.tsx`, `src/lib/ohlc-generator.ts`, and elsewhere. Recommend a dedicated, low-risk formatting/typing cleanup pass (with `--fix` and per-file review), not mixed into behavioral changes.
- **String-matching outcome classification** (M2) — fragile but functional; refactor carefully with the golden harness as a guard.
- **No AbortController** through the market-data fetch path; bounded retries mitigate the worst case but can't cancel a hung upstream TCP connection from the UI (the route does enforce a 20s upstream timeout server-side).
- **Global error capture** (`error-capture.ts`) is best-effort and concurrency-unsafe; acceptable for a diagnostic, but a request-scoped mechanism would be more correct under load.
- **`any`-typed data flow** from Twelve Data response → candles → SVG → ZIP. The API boundary should eventually validate/coerce fields (e.g. guard `parseFloat` NaN) rather than trust the payload shape.

---

## 7. Deliberately NOT changed (and why)

- **Strategy definitions & analyzer math** (`final-survivors.ts`, `spec-strategies.ts`, `status.ts`, `turtle.ts`, etc.): frozen and golden-locked. Changing them — even "obvious" improvements — would invalidate locked backtests. No behavior changed.
- **Repo-wide lint/format fix**: would be a large preference-driven rewrite with regression risk, against the "small deliberate edits" constraint. Left as documented tech debt.
- **`noUnusedLocals`/`noUnusedParameters`**: enabling would surface many pre-existing issues and risk a noisy diff; deferred to a dedicated cleanup cycle.
- **`parseTime` EAT hardcode (L4)**: consistent with the pipeline's EAT commitment; centralizing timezones is a larger refactor than the risk justifies.
- **`error-capture.ts` global state (M3)**: best-effort diagnostic; request-scoped rework out of scope for a hardening pass.
- **`chart.tsx` `dangerouslySetInnerHTML`**: static theme/CSS table, not user input — not a vulnerability.
- **Outcome string-matching (M2)**: short-circuits on the structured field in the live path; refactoring the fallback needs the golden harness as a safety net and a dedicated review.
