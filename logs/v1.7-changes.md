## 1. Bugs fixed

| # | File | Problem | Fix |
|---|---|---|---|
| B1 | `src/lib/analyzer/status.ts#parseTime` | `T`-separated datetimes (e.g. `2025-01-06T09:30:00`) were parsed **without** an offset, so they were interpreted in the engine's local timezone, while space-separated datetimes got `+03:00` appended. The two forms of the same timestamp could therefore disagree by the host UTC offset, skewing `elapsedMinutes` for the Crabel ORB breakeven timer. | Normalise the separator to `T`, detect an explicit `Z`/`±HH:MM` offset, and append `+03:00` (EAT) **only when absent** — identical to `structure.ts#parseDatetimeMs`. |
| B2 | `src/lib/ohlc-generator.ts` (swing-detection comment) | Comment claimed a swing needs "10 candles on each side"; the code uses `SWING_LOOKBACK = 3` (and the user-facing README text correctly says 3). | Corrected the comment to `SWING_LOOKBACK (= 3)`. |

Neither fix touches a trade-generation path in the golden run (all golden fixtures use space-separated EAT timestamps), which is why the golden is unchanged.

### 2.4 `AnalysisContext` trimmed (`types.ts` + `run.ts`)
Removed fields that were populated on every run but **never read**: `ema50`, `ema200`, `blocks`, `asian`, `htfTrendAt`, `enableHtfDirectionFilter`.
- `candle.htfTrend` (per-candle HTF context) is untouched and still computed.
- `structure.ts#htfAllowsDirection` display helper is untouched.
- `RunOptions.enableHtfDirectionFilter` is **kept** for call-site compatibility (UI, tests, golden generator pass it); its doc comment now states it is not stored on the context. `tests/consume-after-rr.test.mjs` continues to assert it is a no-op.
- Side effect: two EMA passes (50, 200), a session-block pass and an Asian-range pass are no longer computed per run — a small CPU win with zero output change.
