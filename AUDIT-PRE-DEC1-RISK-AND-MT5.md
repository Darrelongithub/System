# Pre-Dec-1 MT5 risk audit

## Status: implemented safeguards require MT5/broker validation; NOT certified live-ready

This change is confined to the MT5 files, panel, MT5/risk tests and this audit. It does **not** change the frozen analyzer or golden fixtures. The sandbox cannot contact the ForexFactory feed (outbound network restrictions) and does not contain MetaTrader or MetaEditor: the generated EA has **not** been compiled or executed against a broker. Passing TypeScript and source-level tests does not validate MQL compilation, broker execution, timing, account accounting, or suitability for live capital.

## Calendar and position protection

- Fabricated recurring events are removed. The server fetches the ForexFactory weekly JSON, caches for 15 minutes, backs off on errors (including `Retry-After`), and reports `live`, `stale` or `unavailable`. The news filter defaults on; when enabled, unknown or stale calendar state blocks server entries. Manual JSON can be uploaded via the panel; events supplement the feed but do not certify coverage or change unavailable status. Manual events are memory-only and must be re-uploaded after restart. The weekly feed may not cover the next week; `live` means recently fetched, not guaranteed future coverage.
- Every 10 seconds and on terminal telemetry, the server can close affected positions or queue a protective SL-to-entry MODIFY for profitable positions in the configured pre-news window. The EA supports MODIFY with magic-number checking. Independently, the generated EA queries the native terminal calendar for USD high-impact events, blocks entries on query failure and can close or move profitable positions before news via `InpPreNewsAction`.

## Capital and execution controls

- Server risk state uses account equity versus an EAT-day high-water baseline and an all-time high-water baseline, latches daily percentage/R and total percentage breaches, optionally queues daily flattening, always queues total flattening, and disables new automation on total breach. Defaults: 2%, -3R and 6%. It checks telemetry on every heartbeat and on the 10-second daemon timer. Broker R and consecutive-loss inputs must be available or live entries fail closed. Simulation accounts compute R from initial position risk; the terminal records initial cash risk for new EA trades and reports R including same-day floating P&L and available entry/exit fees. Untracked or carryover positions/deals make R unavailable rather than inventing a risk basis. A four-SL/four-hour cooldown is configurable. Close/modify commands are requests, **not broker-confirmed execution**.
- EA independently persists broker-day and all-time baselines and latches, blocks entries, and attempts to flatten its own magic positions on the configured percentage limits. Its broker-day reset can differ from the server's EAT reset; the server adopts terminal baselines and locks. Initial baseline on first installation or after loss of terminal globals is the first observed equity/balance, not historical midnight or account inception. Deposits, withdrawals, broker clock changes, account migrations and reinstallation can distort these baselines. Limits must be reconciled with the firm's actual rules. The total lock has no panel reset; restoring service requires an explicit audited operational procedure.
- The server checks a fresh, symbol-matched bid/ask and blocks gold spreads above $0.50 by default. The EA checks live quotes, point and XAU/GOLD price spread caps, SL side and broker volume constraints; telemetry contains bid, ask and spread. It rejects zero magic numbers and non-hedging account modes. EAT rollover and Friday blackout are checked server- and terminal-side, with optional gold flatten at the configured Friday close. The EA's input settings are **independent** of the panel's server settings and must be configured consistently. `InpMaxSpreadPoints=50` may be more restrictive than $0.50 depending on broker point size.
- `risk_amount` uses cash budget × risk multiplier divided by SL distance × contract size; risk-sized volume is floored to 0.01 and rejected when the minimum lot exceeds the budget. XAU/USD was already the only default symbol. Gold and common suffix aliases are recognized. Contract sizes and volume steps must still be verified against each broker; the EA rejects volumes that do not match its symbol specification rather than rounding them up.

## Bridge, administration and restart behavior

- OPEN commands have a 90-second TTL, enforced on the server and again by the terminal against UTC with a clock-skew check. The EA reports `FILLED`, `REJECTED`, or `UNKNOWN` with command id, ticket, price, retcode and an error on its next sync. Terminal claims and results are persisted in terminal global variables; the server removes the corresponding optimistic slot on a result or expiration. Only broker telemetry creates a confirmed open position; a successful `CTrade` method return by itself is not treated as a fill. Lost responses are retried. A crash between claiming and recording a broker result is **UNKNOWN**, not proof of rejection; reconcile deals manually. An OPEN can expire after being executed but before its result reaches the server, so reconcile telemetry/deals before taking further action.
- A mode-0600 JSON runtime snapshot at gitignored `output/mt5-runtime-state.json` (override `MT5_RUNTIME_STATE_PATH`) atomically persists config, account identity, bridge token, risk baselines and latches, recent signal keys, and pending commands. The bridge token is a secret and this file must be protected and backed up accordingly. The default output directory is ignored; operators must ensure any overridden location is also excluded from source control. `MT5_STATE_DISABLED=1` disables persistence for isolated tests. Corrupt/unwritable state disables entries. Filesystem durability, locking, backup and permissions depend on the host; this is single-process storage and is **not** a multi-instance/distributed ledger. The terminal still supplies actual positions on reconnect.
- With `MT5_ADMIN_TOKEN` set, mutating `/api/mt5` and EA source download require that bearer token or `x-mt5-admin-token`; the token is held in browser session storage. An unset token preserves unrestricted local-development behavior, so set it on every exposed deployment; the server warns when automation is enabled without it. GET status remains public, and access controls and TLS must still protect the deployment. Bridge requests continue using the separate bridge token. The bridge token is restored from runtime state, and may change if state is lost or credentials are rotated.
- At-most-once terminal claims do not guarantee exactly-once broker execution after a terminal crash or partial broker fill. Close/modify acknowledgments are still not execution-result reconciliation. Flattening intentionally affects only this EA's magic positions; other account positions are not closed. Do not use multiple terminals against one queue. Broker stop/close/modify requests may be rejected, delayed, partially filled or slipped; no code can guarantee protection through a gap or a disconnected terminal. Test all behavior and return codes on the intended broker demo account before live deployment.
