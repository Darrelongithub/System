## 1. Confirmed bugs found in THIS audit (all execution-evidenced, all fixed)

Classification: MAJOR when behavior/data materially wrong on realistic input; MODERATE when the impact requires hostile/extreme input or a specific mode; MINOR for narrow/cosmetic defects.

### F1 — Impossible/non-finite trades can surface as PASS rows — **MODERATE** · FIXED

- **Root:** `applySpreadAndRR` (math.ts) had no finiteness/positivity gate; the downstream `rr <= 2` reject silently _passes_ `NaN` and `Infinity` because both comparisons evaluate false.
- **Evidence:** a single valid-geometry candle with 1e308-scale prices → **13 PASS rows carrying `rr ∈ {Infinity, NaN}`, `tp = −Infinity` or negative (`−3.2e307`), `sl = ±Infinity`**. UI/reports would display impossible trades.
- **Fix (math.ts):** reject when entry/sl/tp are non-finite or ≤ 0 (new `IMPOSSIBLE_PRICES_REASON`), and reject non-finite RR (`NON_FINITE_RR_REASON`, covers denormal-risk overflow) — the row becomes FAIL with a reason instead of a corrupt PASS.
- **Regression:** `tests/math-finiteness.test.mjs`. Golden unaffected (all baseline values sane — verified 0 mismatches after fix).

### F2 — Live reports resolve trades on the untrusted final bar — **MODERATE** · FIXED

- **Root:** with `seriesEndsComplete=false` (AnalysisV2 live mode) the final bar is excluded from _signal generation_ but `evaluateSetupStatus` still resolved trades **with it**.
- **Evidence:** crafted file where the final bar spikes through a live trade's SL → trigger at bar 132 reported **RESOLVED SL at the untrusted final bar** in live mode; after fix it correctly reports FILLED/OPEN. ("Now" for resolution is now the last signal-eligible bar.)
- **Fix (run.ts):** status evaluation receives the trimmed prefix (`candles.slice(0, signalLimit)`) when the series end is incomplete; one shared slice keeps index-keyed caches stable. Complete-series path (golden, Backtest) untouched.
- **Regression:** `tests/live-final-bar.test.mjs` (3 cases incl. an anti-vacuous-fixture guard).

### F3 — Invalid candle-0 value contaminates EMA/MACD signals — **MODERATE** · FIXED

- **Root:** `emaClose` (final-survivors.ts) seeded `e = candles[0].close` _without_ the invalid guard used for every later candle.
- **Evidence:** identical files except candle-0 invalid with close=X vs close=999999 → **different MACD-cross trade sets** (signal at bar 155 vs 156, altered entry/SL/TP, extra short at 148). Excluded data was leaking into a production strategy.
- **Fix:** seed from the first _valid_ close. Behavior identical for all-valid files (golden locked).
- **Regression:** `tests/ema-invalid-seed.test.mjs`.

### F4 — Spread mis-parse: forex spreads 10,000× too small — **MODERATE** · FIXED

- **Root:** `parseSpread` multiplied the _first number_ by 1e-4 whenever the word "pip" appeared **anywhere later** in the convention string. The app's own generated metadata for forex pairs (`"EURUSD: static estimate of 0.0002 price units (approximately 2 pips)…"`) therefore parsed as **2e-8** (intended 2e-4); USDJPY as **2e-6** (intended 0.02). XAU/XAG/BTC/ETH strings contain no "pip" and were accidentally correct.
- **Evidence:** parsed the generator's own templates across symbols before/after (2e-8 → 0.0002; 2e-6 → 0.02; XAU stays 0.2 — golden-safe).
- **Fix (parse.ts):** prefer the first number _not itself pip-qualified_; convert only when every number is pip-qualified. Also hardened: digits inside symbol names (e.g. `US30:`) are never treated as prices.
- **Regression:** `tests/parse-spread.test.mjs` (9 cases incl. `US30`, pip-only conventions, fail-closed garbage).

### F5 — Unbounded, uncancellable provider retry loops — **MODERATE** · FIXED

- **Root:** `buildOhlcCsv` recursed into itself after every 60 s rate-limit wait with **no cap**; DataGenerator's `fetchCandleData` spun in `while(true)` the same way. Neither responds to Stop/cancel during the wait — unbounded API-credit burn, log growth, and the Backtest Stop button is inert mid-fetch.
- **Fix:** hard budget `MAX_RATE_LIMIT_RETRIES = 5` on both paths with explicit progress logs and a terminal, descriptive failure (`null`/`[]`) instead of infinite recursion.
- **Regression:** `tests/rate-limit-retry-cap.test.mjs` (stubbed 429-noticed fetch; pre-fix code would hang the test: terminal path asserts exactly one upstream attempt, terminal log, `null`).

### F6 — NY opening-range mis-keys the post-midnight tail hour — **MINOR** · FIXED (legacy ORB path only)

- **Root:** the NY session runs 16:00→00:59 EAT, but `openingRanges`/`openingRangeFor` keyed candles by _calendar_ day. A 00:30 EAT candle was pointed at its _calendar day's_ 16:00 range — 15.5 h in the bar's **future** — so the last hour of each NY session was structurally unable to trade its own session's opening range (the `i < or.afterWindow` no-lookahead guard could never pass).
- **Evidence:** unit PoC: tail candle at 00:30 resolved to `day=D, afterWindow>D's 16:00 range` → untradeable; after fix maps to `day=D−1` and the prior day's closed range.
- **Fix (daily.ts):** new `openingSessionDay(datetime, session)` — NY candles before 16:00 EAT belong to the session that opened the previous EAT day. Month rollover covered.
- **Regression:** `tests/ny-session-tail.test.mjs`. Golden unaffected (ORB not in the locked production set).

### F7 — Journal MAE/MFE inflated by pre-fill excursion — **MINOR** · FIXED

- **Root:** `walkTradePath` measured excursion from the _trigger bar_, not the actual fill: pre-fill spikes padded MFE for limit/stop orders, and the pre-close body of a market fill bar padded both MAE/MFE.
- **Evidence:** limit-short with a 2.96R pre-fill dip reported `mfeR=2.96`; now `1.0` (fill bar onward, documented intrabar convention). Market-order case: mae 2.0→1.2, mfe 2.0→0.2 after excluding the fill bar's pre-close body.
- **Fix:** `evaluateSetupStatus` now exposes the actual `fillCandle` (generic + ORB paths); the journal starts excursion at the fill (market: next bar after the close-fill).
- **Regression:** `tests/journal-excursion.test.mjs` (3 cases incl. never-filled ⇒ zero excursion).

### F8 — No executable test suite / golden harness in the repo — **TEST GAP (material)** · FIXED

- Prior audits produced `artifacts/*` goldens but **no runnable tests and no npm test entry** — nothing re-verified the lock.
- **Fix:** dependency-free suite under `tests/` (Node's `--experimental-strip-types` + a tiny resolver hook for `@/` and extensionless TS imports — _no new dependencies_, bun.lock untouched). `npm test` (28 tests incl. golden row-level gate, causality battery, accounting invariants, determinism, and one regression per fix F1–F7) and `npm run test:golden`.

### Supporting hardening (juking-adjacent guards, also regression-tested)

- **Swing-ref causality guard (structure.ts):** `similar_swing_refs` pointing to a _future or self_ row now resolve as `unresolved` instead of silently shaping that row's trend with lookahead data. Evidence: 44,652 baseline refs — 0 forward, 0 self ⇒ no-op on legit data (verified); previously a hostile CSV could paint trends from the future (production strategies don't consume trend — cosmetic/report-level ⇒ MINOR class, fixed anyway as a causality boundary).
- **Provider head-truncation observability (ohlc-generator.ts):** Twelve Data caps responses at `outputsize` (5000) **and silently drops the oldest rows**. For the Turtle 120 d lookback even _single-day_ backtests request >5000 bars (e.g. 126 d × 48 ≈ 6048) ⇒ ~26 warm-up days were silently missing while the UI claimed the full window in the queued-line. Now an explicit ⚠ log reports the measured gap (`earliest provider row … N days after requested start`). Warn-only by design.
- **Deterministic ATR spot-check (ohlc-generator.ts):** replaced `sort(() => Math.random() - 0.5)` sampling with a deterministic stride sample — the validation gate no longer depends on RNG luck (pre-fix it effectively always caught NaN regions by sheer density, but non-deterministically).

## 5. Remaining MINOR items & recommendations (deliberately not changed here)

1. **HTF comparison is a no-op (perf + misleading UI).** `compareHtfDirectionFilter` pays **2.33 s** on the baseline to prove 0 differences across 16 strategies — `enableHtfDirectionFilter` is consumed only by two orphan strategy files (baseline/filtered runs always match). AnalysisV2 then runs it _plus_ the main run synchronously: ~**3.6 s of frozen main thread** per CSV on 9.7k rows (measured: parse 0.21 s, run 1.31 s, compare 2.33 s). _Recommend:_ compute the comparison lazily/derived of the single run, or drop the toggle; move engine runs into a Web Worker.
2. **Stop/cancel ergonomics:** Backtest Stop halts at the next _day boundary_ — it does not abort the in-flight OHLC fetch or an in-flight AI call; on stop, already-collected partial results are committed. DataGenerator has no cancel at all and a dead legacy "resume" branch. _Recommend:_ thread the stop flag into the fetch/AI awaits; label partial commits explicitly.
3. **AnalysisV2 stale-bundle key:** auto-bundle dedupe key = `lastRowDatetime` only — a _different_ CSV with the same last datetime suppresses re-bundling. _Recommend:_ key on content hash.
4. **Dead code:** `analyseDay`, engine's localStorage `loadState/saveState/clearState`, journal `walkTradePath`-adjacent helpers, `monthWindowStart`, `STANDARD_LOOKBACK_CALENDAR_DAYS`, 13 orphan strategy files (stale HTF wiring), `buildLiveReport/downloadReports`, `generateMockCandles`. _Recommend:_ delete or fence behind a dev flag; the diagnostics registry self-describes as "temporary, not meant to ship".
5. **API hardening nits:** `/api/analysis` zod strings have no size caps (CSV is trimmed to 60 k chars _after_ parse — the raw body is unbounded), no upstream timeout on the Twelve Data call, and verifier failure text echoes missing env-var _names_ (no values) into the client log. _Recommend:_ body-size cap, `AbortSignal.timeout`, generic error text.
6. **Journal path:** MAE/MFE excursion now starts at fill (F7). The remaining, unavoidable intrabar ambiguity on the fill bar itself is documented convention; no further action short of two implementations (rejected).
7. **Error surfaces:** Verifier "FAILED: …" strings go into downloadable day reports — fine, but keep scanning for provider messages that could contain sensitive text before shipping reports to third parties.
